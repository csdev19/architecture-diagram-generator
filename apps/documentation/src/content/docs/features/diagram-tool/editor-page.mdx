## What It Does

A full-window canvas you draw architecture diagrams on. Tiles are dragged in
from a palette, boxes are dragged out around them, edges are two clicks, and
everything exports as SVG or a 2x PNG.

The JSON is still there — a collapsible panel on the right — and it is still the
only state on the page. Every gesture rewrites it, and every edit to it redraws
the canvas.

### Key Logic

The page holds one piece of state: the textarea's text. The **document**, the
**resolved diagram** and the error list all derive from it in a single memoised
pass — `text → parse → validateDiagramDocument → resolveDiagram` — and the last
one that resolved is kept so a half-typed keystroke does not blank the canvas.
Two derived views, one truth: the document answers what the architecture is,
the resolved diagram answers where everything sits.

The canvas is a camera over an unbounded plane. `useStageView` tracks the world
point at the centre of the window and a scale, turns them into the rectangle
currently visible, and hands that to `renderSVG` as an explicit frame — so the
paper and grid reach every edge of the window and nothing is off-canvas. Export
calls the same renderer with no frame and gets the one the diagram implies.

Every gesture is a text transformation, and each one writes to exactly one half
of the document. A drag reaches `layout.nodes`; a rename reaches `content.nodes`;
an edge's label is content while the sides it leaves and arrives at are layout.
Hit-testing reads the resolved diagram's coordinates rather than measuring the
DOM, and prefers a tile over the boundary it sits in.

Two rules keep that honest. **Layout is materialised on first touch**: auto-layout
is a function of the whole document, so supplying a position for one tile can
legally move the tiles that had none, and a gesture that moves one thing must
move one thing. So the first touch writes down what is already on screen.
**Escape restores the text the gesture began with**, which undoes the settling
as well as the movement — the only undo that cannot miss a detail, because it is
the same single source of truth every edit went through on the way in.

## Decisions

| Decision                                         | Why                                                                                                                                                                                         | Alternatives Considered                                               |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| The canvas is the window; panels float over it   | A column takes its width from the diagram permanently, read or not. Floating means closing the JSON hands the space straight back                                                           | A three-column grid                                                   |
| The renderer draws the editor's surface too      | Passing the visible rectangle as a frame means what you look at and what you export come from one function, background and grid included                                                    | A CSS grid behind a separately rendered sheet                         |
| Everything derives from one state value          | Any second source of truth eventually disagrees with the text on screen                                                                                                                     | Holding a parsed document alongside the raw text                      |
| The last valid document keeps drawing            | Half of authoring JSON is spent in states that do not parse. Losing the picture at each one makes the panel unusable                                                                        | Blanking the canvas on any error                                      |
| Mutations never validate before writing          | An edit that breaks the document is written anyway and reported in the existing error list. Silently refusing a keystroke leaves the author with no idea what happened                      | Rejecting edits that would fail validation                            |
| Hit-testing reads the diagram, not the DOM       | The renderer already fixed every tile's coordinates. Measuring the rendered SVG is a second source of truth that stops agreeing the moment the view is scaled                               | `document.elementFromPoint`, or per-tile DOM listeners                |
| Each gesture writes to one half of the document  | A drag says where something sits and nothing else. Splitting the edits into two modules makes that visible at the call site as well as in the diff a drag produces                          | One module of mutations reaching wherever it needs to                 |
| Layout is materialised on first touch            | Pinning one tile can move the tiles that were never pinned, which is correct for a document and wrong for a gesture. Writing down what is on screen first makes the two agree               | Letting the drawing re-flow, or memoising positions outside the text  |
| Escape restores the text, not the position       | A gesture settles the layout before it moves anything, so putting one coordinate back would leave the rest of its work in place                                                             | Restoring the dragged node's original coordinate                      |
| Deleting dissolves a group left with no node     | The gesture was reasonable and the result would not validate. Repairing it beats reporting it — and the boundary that stops being framed is handed the rectangle it had on screen           | Reporting the invalid document and letting the author fix it          |
| A click selects the outermost group              | A group reads as one object, so pressing any part of it picks the whole. Entering it with a double-click is what reaches the elements inside — the model Figma, tldraw and Excalidraw share | Selecting the element and treating the group as a label               |
| One selection kind, several ids                  | The bin, the Delete key and the inspector all need to know _what_ they are looking at. Separate node and boundary ids would let both be set and make every reader invent a tie-break        | `selectedNodeId` and `selectedBoundaryId` side by side                |
| A tile wins over the boundary containing it      | The tile is the smaller, more specific target, and it is drawn on top                                                                                                                       | Requiring a click on the boundary's border                            |
| Chrome is drawn in an overlay SVG                | Halos and the boundary being dragged out never enter the scene, so the exported document is the renderer's output byte for byte — with nothing to strip                                     | Marking chrome inside the scene and removing it on export             |
| A group drag snaps the delta, not the positions  | Rounding each member to the grid separately moves them by different amounts and shears the group apart. Snapping once keeps every internal distance exactly as it was                       | Snapping each member's new position                                   |
| A grouped boundary has padding, not a rectangle  | Its geometry is derived from what it frames, so a rectangle in the inspector would be a field that cannot be honoured. `tight`/`normal`/`loose` is the same choice, made where it belongs   | Resize handles that write a rectangle and lose it on the next resolve |
| A drawn boundary lands neutral, named `BOUNDARY` | The tone is a claim about the system and the label is the author's words. Neither is something a drag can guess, so it opens in the inspector instead                                       | Prompting for a name mid-gesture                                      |
| Deleting a boundary keeps its tiles              | A boundary is a box drawn around nodes, not a parent of them — which is what makes trying one cheap                                                                                         | Cascading the delete to everything inside                             |
| The editor runs its own chrome theme             | The app shell forces `.dark` on `<html>`; the editor reads `data-chrome` on its own root, so its light and dark palettes are independent of the rest of the app                             | Reusing the app's shadcn tokens                                       |
| Local chrome primitives, not `web-ui`            | The shared components carry `dark:` variants keyed to `.dark` on `<html>`, so inside the editor they would follow the app's theme rather than the editor's                                  | Overriding the shared components per instance                         |
| Enum fields are native `<select>`s               | A dense panel of small controls keeps keyboard behaviour, label association and screen-reader semantics for free, without a portal per field                                                | The design system's base-ui `Select`                                  |

## Gotchas & Warnings

- ⚠️ A group is never drawn. The dashed rectangle around a selected one is an overlay, and anything that puts it in the exported SVG is a bug.
- ⚠️ Any mutation that can re-flow the drawing must go through `settled` in `useDiagramEditing`, which materialises the layout first. Skipping it means a gesture that touches one tile visibly rearranges the others.
- ⚠️ A gesture that writes has to call `onGestureStart` before it does, or Escape has nothing to restore.
- ⚠️ `layout.nodes` is keyed by node id and `layout.edges` by edge id, so anything that deletes an element has to delete its entries in the same edit. A key naming something that is gone is a validation error, not a silent drop.
- ⚠️ The route must stay outside the `_authenticated` segment, and it is the only route in `FULL_SCREEN_ROUTES` in `__root.tsx` — that list is what hides the app navbar so the canvas can own the window.
- ⚠️ The scene SVG is rebuilt on every camera move, because the frame _is_ the camera. That is fine at the 40 nodes the schema allows and would need a dirty-region pass long before it needed a canvas library.
- ⚠️ PNG export depends on the SVG being fully self-contained. Adding a remote `<image href>` to the renderer would taint the canvas and make `toDataURL` throw.
- ⚠️ `EditorPage` lives in `components/`, not in the route file. A `__tests__` directory under `src/routes/` would be picked up as a route by the file-based router.
- ⚠️ jsdom performs no layout, so every element reports a zero size and the camera has no viewport — nothing renders. `src/vitest.setup.ts` makes elements report a fixed one; removing that stub makes every canvas test fail in a way that points at the component.
- ⚠️ jsdom implements neither `PointerEvent` nor `DragEvent`. Testing Library downgrades both to a plain `Event` and drops `clientX`/`clientY`, so a gesture test fires perfectly and carries no coordinates. Both polyfills live in the same setup file.
- ⚠️ jsdom implements no SVG geometry either, so `getScreenCTM` is stubbed per test file. `clientToViewBox` solves the matrix by hand rather than via `DOMPoint`, which jsdom also lacks.
- ⚠️ Testing Library only auto-registers cleanup under `globals: true`. The setup file wires `afterEach(cleanup)` explicitly — without it renders stack in one document and queries fail with "found multiple elements".
- ⚠️ The test rig keeps `vite-tsconfig-paths`. `@diagram-tool/web-ui` defines a `@/` alias of its own, and a single app-level `@/` alias hijacks it and breaks every import inside that package.
- ⚠️ The wheel listener is attached natively, not through `onWheel`. React registers wheel handlers as passive, so `preventDefault` there cannot stop the page scrolling behind the zoom.
- ⚠️ Auto-fit stops the moment the author zooms by hand. Without that, opening a panel or adding a tile would undo a deliberate zoom; `Fit` hands control back.

```bash
# Unit and component tests
bun run test --filter=fullstack-fn-only

# Manual testing
bun run dev:fullstack-fn
# Open http://localhost:3002/editor
# 1. The example renders on load, filling the window — no sheet, no table.
# 2. Drag a tile off the palette onto the canvas, far from everything else.
# 3. Drag it again — the JSON's coordinates follow and snap to the half-grid.
# 4. Press Escape mid-drag — the node returns to exactly where it started.
# 5. Boundary, drag a box around two tiles, name it and pick a tone.
# 6. Move the boundary — the tiles inside stay put. Delete it — they survive.
# 7. Connect, click two tiles — the anchors face each other.

# 9. File ▸ Export PNG 2x — the PNG is the drawing, cropped to its own bounds.
```
