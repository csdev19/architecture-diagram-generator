## What It Does

A public two-pane page. The config JSON goes on the left, the rendered diagram
appears on the right as you type, and one button downloads it as a 2x PNG. In
phase 0 this is the whole product: ask Claude for a config in chat, paste it
here, export the image.

## Implementation

### Domain Model

N/A — the page consumes the domain model without extending it.

### Key Logic

The page holds exactly one piece of state: the textarea's text. The SVG, the
title and the error list are all derived from it in a single memoised pass, so
the preview cannot disagree with what is written. Invalid JSON and an invalid
config surface through the same channel — both are just problems to fix. PNG
export serialises the SVG into a blob, draws it to a canvas at twice its size,
and triggers a download.

## Decisions

| Decision                                | Why                                                                                                                                                                                         | Alternatives Considered                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| No server function is involved          | The hub reserves server functions for cookie and header work on the web server. Rendering needs neither, so it runs in the browser                                                          | A `createServerFn` that renders server-side    |
| The SVG is injected as markup           | Rebuilding it as a React tree would mean a second renderer, and the exported image could then differ from the preview. The markup is our own output, from a validated config, fully escaped | Parsing the SVG into React elements            |
| Everything derives from one state value | Any second source of truth eventually disagrees with the text on screen                                                                                                                     | Holding a parsed config alongside the raw text |
| The route is public                     | Phase 0 has no accounts, and the plan explicitly defers multi-user auth                                                                                                                     | Placing it under the authenticated segment     |
| Seeded with the canonical example       | The page is useful on first load, and there is one example to keep correct rather than two                                                                                                  | An empty textarea                              |

## Gotchas & Warnings

- ⚠️ The route must stay outside the `_authenticated` segment. Moving it in would put a tool that needs no account behind a login.
- ⚠️ PNG export depends on the SVG being fully self-contained. Adding a remote `<image href>` to the renderer would taint the canvas and make `toDataURL` throw.
- ⚠️ The two-pane layout uses `md:grid-cols-2`, an app-only responsive utility. If `packages/web-ui` ever imports a stylesheet in its `src/index.ts` again, that class loses the cascade in production builds while still working in dev.
- ⚠️ The page has no automated test. The app ships no Vitest config, and a route test would first need jsdom, RTL and the React dedup block from the hub's testing guide.

## Dependencies

None new. Uses `@diagram-tool/domain` and existing `@diagram-tool/web-ui` components.
