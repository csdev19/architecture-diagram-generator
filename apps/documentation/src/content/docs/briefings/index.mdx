# Briefings

Each page below answers **"what is this project?"** in one read, without
following links. They differ by who is asking, so start with the line that
describes you.

- [Pitch](/briefings/pitch) — **a person deciding whether to care.** What problem
  this solves, what a diagram config looks like, and who it is honestly not for.
- [Roadmap](/briefings/roadmap) — **anyone asking "where is this?"** What is
  merged, what is open in review, and the one phase that is committed but not
  started.
- [AI Briefing](/briefings/ai-briefing) — **another model.** Paste it whole: the
  full `DiagramConfig` schema, every limit, the 20 icon keys, and the mistakes a
  model reliably makes about this codebase.
- [Stack](/briefings/stack) — **a developer evaluating the foundations.** Every
  load-bearing dependency and why it is here — separating what was chosen for
  the diagram tool from what came with the template.
- [Design Brief](/briefings/design-brief) — **anyone changing how a diagram
  looks.** The palette, type and geometry of the rendered SVG, and which colours
  carry meaning rather than decoration.

These are summaries with a shelf life, and they say so: the ones meant to be
pasted into a model carry a "current as of" date, and the roadmap carries a
review date. They are not the detailed documentation. For how a specific piece
works, read the [Diagram Tool](/features/diagram-tool/) feature docs; for what
changed and why, the [Changelog](/changelog/); for the working agreements of the
repo itself, `CLAUDE.md` at the root.
