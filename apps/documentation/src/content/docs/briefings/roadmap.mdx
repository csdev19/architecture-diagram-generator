`gh pr list --state merged` and `--state open` — not from the plan documents in
`docs/plans/`, which record intent and lag reality. There are no git tags and no

The spike settled the one question that blocked the whole server-side phase:
Cloudflare Workers refuse runtime WebAssembly compilation, so the wasm has to be
a **bundled import** compiled at deploy. Fetching the binary and instantiating it
fails with "Wasm code generation disallowed by embedder". The assets binding
stays viable for data — which is how fonts will load — but never for code.

## Next

Committed direction, not started. This is the whole of it — there is no backlog
beyond this list, and nothing here has a date.

**Finish the server-side render and the MCP server** (`docs/plans/2026-09-01-diagram-tool-next-phases-02-api-mcp.md`,
Tasks 2–6). Paused by an explicit decision on 2026-09-01 in favour of building
the visual editor first. It matters because it is the half of the original
thesis that does not exist yet: today a person pastes a config into the editor
by hand, and the point of the project is that a model hands one over directly.
The remaining tasks are font embedding, an R2 store with REST endpoints, loading
a saved diagram by id in the editor, the MCP endpoint itself, and deployment.

Two of those cannot be done from the repo alone: the store needs a Cloudflare
account with a bucket and a secret, and registering the MCP server as a
connector is a manual step in the Claude interface. That is why the phase was
paused rather than pushed through.

**Known smaller gaps**, recorded so they are not rediscovered:

- Auto-layout re-places nodes but leaves group boxes where they were, so
  **Arrange** breaks a hand-composed grouped diagram. `layoutDiagram` would need
  to recompute each group's box from the nodes it contains.
- The icon registry has 20 keys. Anything outside it falls back to an emoji,
  which works as designed but is the obvious thing to grow with use.
