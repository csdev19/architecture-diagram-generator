## In flight

### The canvas rebuild

One branch, open for review. It is a rewrite of the editing surface plus the
domain change that made it possible, so it is worth reading as one thing:

- **The frame is derived, not declared.** `canvas: { w, h }` became optional and
  `renderSVG` sizes the document from the bounding box of what the diagram
  contains. Coordinates are unbounded — negatives included — and the margin rule
  is gone from the schema. Recorded in
  [ADR 0002](/architecture/decisions/adr-0002-the-frame-is-derived-not-declared).
- **`/editor` is a full-window canvas.** The palette and the JSON panel float
  over it and both close. Tiles are dragged in from the palette, groups are
  dragged out as boxes, and the five tools are labelled rather than left as
  glyphs.
- **The renderer draws the editor's surface.** It takes an optional frame, and
  the editor passes the rectangle its camera is looking at — so the paper and
  the grid come from the same function that produces the PNG.
- **Paper is a choice of five near-whites**, named in the config as
  `background` rather than picked as a hex.

Until it merges, `main` still has the two-pane editor and a required `canvas`.

## Next

Committed direction, not started. This is the whole of it — there is no backlog
beyond this list, and nothing here has a date.

### Finish the server-side render and the MCP server

`docs/plans/2026-09-01-diagram-tool-next-phases-02-api-mcp.md`, **Tasks 2–6**.
Task 1 is done and merged; the rest was paused by an explicit decision on
2026-09-01 in favour of building the visual editor first.

It matters because it is the half of the original thesis that does not exist
yet: today a person pastes a config into the editor by hand, and the point of
the project is that a model hands one over directly. What remains is font
embedding, an R2 store with REST endpoints, loading a saved diagram by id in the
editor, the MCP endpoint itself, and deployment.

The spike already settled the question that gated all of it. Cloudflare Workers
refuse runtime WebAssembly compilation, so the wasm must be a **bundled import**
compiled at deploy — fetching the binary and instantiating it fails with
"Wasm code generation disallowed by embedder". The assets binding stays viable
for data, which is how fonts will load, but never for code. Two further findings
are written up in that plan file: Vite's dependency scanner misreports the
`.wasm` specifier failure as a stale React pre-bundle, and `wrangler dev` is the
only honest answer to a Worker-runtime question, because `vite dev` never gets
far enough to ask it.

Two of the remaining tasks cannot be done from the repo alone: the store needs a
Cloudflare account with a bucket and a secret, and registering the MCP server as
a connector is a manual step in the Claude interface. That is why the phase was
paused rather than pushed through.

### Known smaller gaps

Recorded so they are not rediscovered.

- **Auto-layout ignores groups.** `layoutDiagram` re-places nodes but returns
  group boxes untouched, so **Arrange** breaks a hand-composed grouped diagram.
  It would need to recompute each group's box from the nodes it contains — more
  obviously worth doing now that groups can be drawn on the canvas.
- **Groups have no resize handles.** A group is drawn at the size you drag it
  out to and adjusted afterwards through width and height fields in the
  inspector. Corner handles are the obvious next step.
- **Server-side rendering draws no text yet.** The spike rasterises with
  `loadSystemFonts: false` and no font buffers, so shapes and logos render and
  glyphs do not. That is exactly what Task 2 fixes.
- **`/api/render-spike` is throwaway** and says so in its own source. It is
  deleted when Task 3 introduces `/api/render`.
- **The icon registry has 20 keys.** Anything outside it falls back to an emoji,
  which works as designed but is the obvious thing to grow with use.
